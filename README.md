# HydroTwin Energy — Wholesale Price Forecasting Twin

A sibling of **HydroTwin** (the river-gauging digital twin). HydroTwin watches
rivers; this twin watches what the rivers are worth: it forecasts wholesale
electricity prices 1–7 days ahead for three hydro-linked price regions by
combining the four HydroTwin data sources — USGS river flow, NRCS SNOTEL
snowpack, NRCS SCAN soil moisture, Open-Meteo weather — with EIA energy data
(ICE day-ahead hub indices republished by EIA, CAISO OASIS LMP, and the EIA
Henry Hub natural gas price).

The concept follows the RIDE deck: in hydro-heavy regions, wet winters build
snowpack, snowmelt raises river flow, and prices soften; dry winters push gas
generation up and prices rise months later. Features are lagged accordingly;
the target is the hub price shifted forward by the forecast horizon.

## Regions

| Region | Price series | HydroTwin gauges |
|---|---|---|
| CAISO NP15 — Northern California | CAISO OASIS day-ahead LMP at TH_NP15_GEN-APND, daily mean | Sacramento R. at Verona (11425500) + American R. at Fair Oaks (11446500) — HydroTwin's Freeport gauge (11447650) is tidal and publishes no NWIS daily-discharge series, so it cannot be used |
| Mid-Columbia — Pacific Northwest | ICE Mid C Peak day-ahead index via EIA | Columbia R. at The Dalles (14105700) + Willamette R. at Portland (14211720) |
| Palo Verde — Southwest | ICE Palo Verde Peak day-ahead index via EIA | Colorado R. at Lees Ferry (09380000) + Rio Grande at Otowi Bridge (08313000) |

An ERCOT North (Texas) region was attempted first and replaced: the EIA ICE
workbooks contain no ERCOT North product, and ERCOT's MIS archive retains only
~1 month of DAM price files, so no genuine multi-year ERCOT hub history is
freely downloadable without an API key. See TRAINING_REPORT.md.

## Layout

- `index.html`, `app.js`, `data.js` — the static site. `data.js` is a dated
  snapshot generated by the pipeline (prices, features, forecasts, holdout
  metrics, model weights). The page is not live data.
- `pipeline/pipeline.py` — fetch → features → train → evaluate → export.
  Re-running it refreshes the snapshot and `TRAINING_REPORT.md`.
- `pipeline/discover_stations.py` — NRCS AWDB station discovery used to pick
  the SNOTEL/SCAN stations.
- `TRAINING_REPORT.md` — per-region sources, row counts, features, holdout
  metrics including the persistence-baseline comparison.

## Model

Per region and per horizon (7 horizons), a model predicts the **signed-log
price change** from the last observed price — persistence ("no change") is
the anchor the features must beat. Two candidates per horizon (ridge
regression; MLP 48→24 hidden units) on standardized engineered features
(price lags/rolling means, Henry Hub gas lags, flow level + anomaly vs
trailing year, SWE, soil moisture, 7-day precipitation/temperature/snowfall,
calendar cycles). The winner is selected on a validation slice (last 20% of
the training period), refit on the full training period, and scored once on
a time-based holdout (last 20% of origins, no shuffling) against the
persistence baseline. Predictions are clipped to the training period's
observed price range (maximum extended 25%). Model weights ship in
`data.js`; the page recomputes the displayed forecast from them in the
browser.

## Deployment

Deployed like the battery twin: a dedicated S3 website bucket
(`hydrotwin-energy-2026`, us-east-1) fronted by its own CloudFront
distribution, via a manual GitHub Actions workflow kept with the project
(`deploy-hydrotwin-energy-aws.yml`, run from the hydrotwin-site repo, which
holds the AWS secrets). This twin does not touch HydroTwin's site, buckets,
distributions, or workflows.

Version 1 is charts, features, and forecasts — no 3D/Cesium scenery.
